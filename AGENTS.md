# Постоянная политика хранения файлов

Эти инструкции применяются ко всем последующим заданиям Codex в этом проекте.
Применять политику немедленно.

- Рабочий проект: `C:\Users\serge\cashback+`.
- Архив и вспомогательные материалы: `D:\Cashback+ archive`.

## Что хранить на C:

Только файлы, необходимые для работы сайта и разработки:

- Исходный код frontend и backend.
- Конфигурации и зависимости проекта.
- Необходимые Docker-ресурсы.
- Активную PostgreSQL и её данные.
- Git-репозиторий.
- Файлы, необходимые для сборки, запуска и тестирования сайта.

## Что сразу создавать на D:

- Резервные копии PostgreSQL.
- Архивы и snapshots.
- Отчёты и диагностические результаты.
- Временные тестовые базы, если технически возможно безопасное размещение на D:.
- Экспортированные данные.
- Скриншоты браузерных проверок.
- Логи отдельных диагностических запусков.
- Временные ZIP-архивы.
- Исторические версии файлов.
- Результаты аудита и инвентаризации.
- Промежуточные материалы, не требующие размещения в рабочем проекте.

При необходимости создавать соответствующие каталоги:

- `D:\Cashback+ archive\backups`
- `D:\Cashback+ archive\reports`
- `D:\Cashback+ archive\diagnostics`
- `D:\Cashback+ archive\temporary`
- `D:\Cashback+ archive\screenshots`
- `D:\Cashback+ archive\exports`

## Ограничения и безопасное обращение с файлами

- Не создавать временные полные копии проекта на C:.
- Не создавать дополнительные Git worktrees без необходимости.
- Не создавать резервную копию перед каждым небольшим изменением кода.
- Не дублировать уже существующие архивы.
- Перед переносом на D: проверять доступность накопителя; удалять оригинал только
  после проверки размера и SHA256 копии и отсутствия зависимости от исходного пути.
- Не переносить работающие Docker volumes и PostgreSQL без отдельного разрешения.
- Не удалять уникальные пользовательские данные.
- Не изменять системные каталоги Windows.
- При необходимости временного файла сначала проверять возможность его создания на D:.
- По окончании задания удалять только подтверждённые ненужные временные материалы.
- Не включать архивы, дампы, секреты и диагностические материалы в Git.

## Выполнение заданий

Все безопасные действия выполнять одним проходом, без промежуточных запросов
согласования, в пределах разрешённого пользователем задания.

Если D: недоступен, не переносить вспомогательные файлы автоматически на C:.
Сообщить о препятствии, если без этих файлов невозможно продолжить работу безопасно.

## Контроль по завершении

В конце каждого крупного задания кратко указывать:

- Какие вспомогательные материалы созданы на D:.
- Появились ли ненужные файлы на C:.
- Сколько свободного места осталось на C:, если выполнялись крупные сборки
  или Docker-операции.

Не создавать отдельный отчёт только ради контроля диска.
